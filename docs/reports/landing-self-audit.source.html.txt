  <section class="hero" aria-labelledby="hero-h">
    <div class="wrap">
      <h1 id="hero-h">Make established accessibility tools usable by every coding agent.</h1>
      <p class="lede">Beacon is an accessibility integration layer for Claude Code and Codex. It combines source inspection, browser measurements, axe-core evidence, supplementary Lighthouse signals, and human testing guidance, then turns the evidence into prioritized fixes anchored to the code.</p>
      <p class="honesty">A high score means automated checks found fewer issues in the evidence available. It is a triage signal — not a compliance certificate, and never a substitute for testing with disabled users.</p>
      <div class="cta-row">
        <a class="btn btn-primary" href="#install">Get started</a>
        <a class="btn btn-ghost" href="reports/landing-self-audit.html">See this page's own audit</a>
      </div>
    </div>
  </section>

  <section id="toolchain" aria-labelledby="toolchain-h">
    <div class="wrap">
      <h2 id="toolchain-h">One workflow, evidence from the right tool</h2>
      <p class="section-lede">Beacon does not replace mature testing engines. It records what each tool actually established, keeps uncertain results visible, avoids counting the same defect twice, and tells the agent what still needs a person.</p>
      <div class="tool-grid">
        <div class="tool-row"><h3>Beacon source inspection</h3><p>Works before deployment and without a browser. Finds code-level patterns, file locations, and agent-ready fixes.</p></div>
        <div class="tool-row"><h3>axe-core</h3><p>Runs against rendered content. Passes, violations, incomplete results, affected nodes, rule links, engine version, and provenance remain intact.</p></div>
        <div class="tool-row"><h3>Lighthouse</h3><p>Adds performance, best-practices, and SEO context. Its accessibility category is not treated as independent evidence because it is powered by axe-core.</p></div>
        <div class="tool-row"><h3>WAVE / WebAIM</h3><p>Planned as an optional independent cross-check when the user supplies access; it is not part of the default workflow yet. Beacon will not bundle a paid API key or present WAVE results as its own.</p></div>
        <div class="tool-row"><h3>Human and assistive-technology testing</h3><p>Covers keyboard task completion, NVDA and VoiceOver, cognitive clarity, motion, and real use. Automated scores never replace this layer.</p></div>
      </div>
      <p class="footnote">The normalized report keeps each source and version visible. Corroborating tools strengthen a finding; they do not create duplicate penalties.</p>
    </div>
  </section>

  <section id="commands" aria-labelledby="commands-h">
    <div class="wrap">
      <h2 id="commands-h">One plugin, three moments</h2>
      <p class="section-lede">Accessibility is cheapest before code exists and most expensive after launch. Beacon meets you at all three points.</p>
      <div class="cards">
        <div class="card">
          <span class="when">Before you code</span>
          <h3><code>beacon:guide</code></h3>
          <p>Accessible patterns, contrast-safe palettes, typography and motion tokens, and design tradeoffs — while the UI is still a sketch.</p>
        </div>
        <div class="card">
          <span class="when">While you code</span>
          <h3><code>beacon:advisor</code></h3>
          <p>A hook reviews every UI edit in real time and hands the agent a concrete checklist for the file it just touched.</p>
        </div>
        <div class="card">
          <span class="when">After you code</span>
          <h3><code>beacon:inspect</code></h3>
          <p>A Lighthouse-style 0–100 report with exact-markup fixes, legal context across 23 tracked jurisdictions (14 with a specific law, 2 framework-only, 7 tracked as no law found), and before/after comparison across runs.</p>
        </div>
      </div>
    </div>
  </section>

      <h3>Every detector carries its own measured precision</h3>
      <p>A score is only as trustworthy as the individual checks under it. Each detector is sampled across distinct real sites nobody hand-picked, judged instance by instance against the markup it cited, then adversarially re-judged by a second reviewer briefed to overturn the first.</p>

      <div class="table-wrap" role="region" aria-label="Measured per-detector precision on unselected real pages" tabindex="0">

      <p class="footnote">Publishing the weak rows is the point: n=15 ranks detectors and exposes error classes, it does not certify any single figure. The leading cause of false positives is markup hidden by a stylesheet class rather than an inline style, which a tier that never loads CSS cannot see. Every per-instance judgement — including the ones the reviewer overturned — ships with <a href="https://github.com/chiehweihuang/beacon/tree/master/benchmark/2026-08-03-wild-precision">the published data</a>.</p>

      <h3>3,700 real-site runs: a research cohort, not 3,700 endorsements</h3>
      <p>The survey supplies diverse pages for finding detector weaknesses, selecting regression cases, measuring release movement, and drawing human-review samples. Site names and captured third-party pages are not published.</p>
      <div class="stats">
        <div class="stat"><span class="n">3,700</span> <span class="d">unique sites with a successful rendered snapshot and normalized audit artifact</span></div>
        <div class="stat"><span class="n">3,625</span> <span class="d">active artifacts in the current aggregate-analysis cohort after status exclusions</span></div>
        <div class="stat"><span class="n">0 named sites</span> <span class="d">public findings are aggregate measurements, not a public ranking of third parties</span></div>
      </div>
      <p class="footnote">The cohort does not prove 3,700 sites were manually audited, that every finding is correct, or that its score distribution measures the accessibility of the web. Read the <a href="https://github.com/chiehweihuang/beacon/blob/master/benchmark/2026-08-13-survey-3700.md">cohort definition and permitted claims</a>.</p>

  <section id="design" aria-labelledby="design-h">
    <div class="wrap">
      <h2 id="design-h">Will it fight your design?</h2>
      <p class="section-lede">Findings fall into three buckets, by their effect on the page's default appearance.</p>
      <div class="stats">
        <div class="stat"><span class="n">No pixels</span> <span class="d">alt text, accessible names, label associations, heading levels, page language, structured data</span></div>
        <div class="stat"><span class="n">State-only</span> <span class="d">appear only in a state the user chose — keyboard focus, a narrow window, reduced motion</span></div>
        <div class="stat"><span class="n">Copy, not style</span> <span class="d">link wording or a CAPTCHA mechanism — content decisions, not visual ones</span></div>
      </div>
      <p>Most accessibility debt is invisible to people it doesn't block. Fixing it doesn't touch your aesthetic — and this page is the demonstration: it is styled freely, audited by the engine it advertises, and the report is one click away.</p>
      <p><span class="badge">This page scores 100/100 (static tier, 23% of scoring weight measured) — read its audit below</span></p>

  <section id="install" aria-labelledby="install-h">
    <div class="wrap">
      <h2 id="install-h">Install</h2>
      <p class="section-lede">One command inside Claude Code, after registering the marketplace.</p>
<pre><code>/plugin install beacon@beacon</code></pre>
      <p class="footnote">The format is <code>plugin@marketplace</code>. This repository is both the marketplace and its only plugin, and both are named beacon — hence the doubled name.</p>
      <p>Add the marketplace to your Claude Code config first:</p>
<pre><code>"extraKnownMarketplaces": {
  "beacon": {
    "source": { "source": "github", "repo": "chiehweihuang/beacon" }
  }
}</code></pre>
      <p>Using Codex instead? Install it as a native Codex plugin:</p>

<pre><code>codex plugin marketplace add chiehweihuang/beacon
codex plugin add beacon@beacon</code></pre>
      <p class="footnote">Restart Codex after installation. See <a href="https://github.com/chiehweihuang/beacon/blob/master/ADAPTERS.md">ADAPTERS.md</a> for the runtime differences.</p>
